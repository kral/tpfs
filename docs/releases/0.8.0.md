# tpfs 0.8.0

## New

- **`tpfs trash` and `tpfs trash empty`.** List what the trash holds per batch, and empty it:
  everything older than 30 days by default, or `--older-than <N>d` / `--batch <id>`. This is the
  one permanent delete in tpfs. It asks for a typed `yes` (or `--approve` naming exactly that
  selection), agents cannot do it, and it is recorded in the journal before anything is removed.
  An emptied batch can no longer be undone, and `undo` and `log` say so. A crash while emptying is
  finished by the next run.
- **Install with `cargo install tpfs`** (once published on crates.io), next to the prebuilt
  binaries.
- **Release workflow:** publishing to crates.io and Windows code signing through SignPath, both
  switched on once their secrets are configured. See [CODE_SIGNING.md](../../CODE_SIGNING.md).

## Found by the new automatic tests, fixed

CI now injects a crash at every point the executor passes through, in runs, undo and recovery
(about 16,600 crash positions over 26 scenarios). It also runs randomly generated plans, checking
that a run either commits and undoes exactly, or leaves everything as it was. The fixes:

- an undo interrupted twice, with a half-written journal line, was refused as "damaged";
- an interrupted recovery of a move across disks left a partial copy, and later recoveries failed;
- merging back after a move across disks lost folder modes and failed on read-only folders;
- undo refused a copy containing symlinks after a round trip across disks;
- a copy of a read-only folder could not be undone (non-root users).

A longer run (all crash positions, 200,000 random plans) runs weekly and on every push to main.
